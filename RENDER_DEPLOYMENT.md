# Render deployment guide

## Read this first

This package uses the same Gmail SMTP method as the previous SecureVote project: `smtp.gmail.com`, STARTTLS, port `587`, a Gmail address, and a Google App Password.

Render Free is not compatible with this exact setup. Free web services block outbound SMTP ports `25`, `465`, and `587`. Free instances also lose local SQLite and ledger files when they spin down or restart. The included `render.yaml` therefore uses a paid Starter web service with a persistent disk.

Do not change the Blueprint to `free` and assume it is fixed. The website may open, but Gmail OTP delivery will fail and election data will not persist.

## Part 1: Prepare the new OTP Gmail account

1. Create the separate Gmail account you want SecureVote to use.
2. Sign in to that account and open Google Account security settings.
3. Turn on 2-Step Verification.
4. Open Google App Passwords.
5. Create an App Password named `SecureVote Render`.
6. Copy the 16-character App Password once. This is the value for `SMTP_PASS`.

Do not use the normal Gmail password. Do not save the App Password in the project files or GitHub.

## Part 2: Upload to GitHub

1. Extract the final ZIP.
2. Create a new GitHub repository or replace the files in the intended repository.
3. Make sure `render.yaml`, `app.py`, and `requirements.txt` are at the repository root.
4. Confirm that none of these files are committed: `.env`, `voting.db`, `chain_data.json`, or `secret.key`.
5. Commit and push the project.

## Part 3: Deploy the Blueprint

1. Sign in to Render.
2. Select **New** and then **Blueprint**.
3. Connect the GitHub repository.
4. Render reads `render.yaml` and asks for the variables marked as not synchronized.
5. Enter:

   | Key | Value |
   | --- | --- |
   | `ADMIN_USERNAME` | A new admin username that is not `admin` |
   | `ADMIN_PASSWORD` | A strong password of at least 12 characters |
   | `SMTP_USER` | The full new Gmail address |
   | `SMTP_PASS` | The Google 16-character App Password |

6. Confirm the Starter service and 1 GB persistent disk cost shown by Render.
7. Apply the Blueprint and wait for the deploy to finish.
8. Open the generated `onrender.com` URL.

`FLASK_SECRET_KEY` and `BALLOT_SECRET` are generated by Render automatically. Do not replace or regenerate them after voters have registered and ballots have been cast. Changing `FLASK_SECRET_KEY` invalidates sessions and OTP hashes. Changing `BALLOT_SECRET` makes existing encrypted ballots unreadable.

## Part 4: Verify the live system

Run this exact check before sharing the link:

1. Open `/health` and confirm it returns `{"status":"ok"}`.
2. Register using an email different from the sender Gmail account.
3. Confirm the OTP arrives and expires correctly.
4. Save the generated Voter ID.
5. Log in with the Voter ID and email, then verify the second OTP.
6. Cast one test vote.
7. Submit or refresh again and confirm a second vote is blocked.
8. Log in as admin.
9. Confirm registration count, vote count, tally, and ledger status.
10. Pause voting and verify that a voter cannot submit a ballot.
11. Resume voting if the election should remain open.

## If OTP email fails

Check the Render logs for `OTP email delivery failed`, then verify:

- The web service is paid, not Free.
- `SMTP_USER` is the complete Gmail address.
- `SMTP_PASS` is the Google App Password, not the account password.
- 2-Step Verification remains enabled.
- The App Password has not been revoked. Google revokes App Passwords after the Google account password changes.
- `SMTP_HOST` is `smtp.gmail.com` and `SMTP_PORT` is `587`.

The application deliberately never falls back to showing the OTP on the production website.

## Updating the project later

Push code changes to the connected GitHub branch. Render redeploys the service, while the attached disk preserves the database and ledger. Back up the three files in `/var/data/securevote` before any major schema change or election reset.
